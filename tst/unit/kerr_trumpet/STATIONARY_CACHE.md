# Experimental stationary background cache

Enable with `problem/cache_stationary_background=true` only in z4c_tov_ks with the audited fixed direct Kerr trumpet provider. Default is false. This is an implementation optimization, not a gauge/constraint modification. Existing ADM and once-projected Z4c background arrays are retained. The evolving full state, RHS, constraints and residuals are never cached or reset. RefreshBackground invalidates the cache; UpdateBackgroundState returns on a valid hit before both provider kernels and projection. Reprojecting a projected background would change floating-point cancellation and is intentionally avoided.

Enrollment/restart begins invalid. MeshBlockPack::AddMeshBlocks and AddCoordinates invalidate on layout replacement, including same-count refinement/migration and allocator reuse. Provider pointers, array data pointers, local count and conformal representation are additionally checked, but pointer/count checks do not substitute for the explicit hooks. Pgen background parameters remain fixed after enrollment; any future mutation must invalidate or re-enroll. Only the known Kerr provider opts in; time-dependent gauge-wave providers remain disabled. No extra volume-sized arrays or per-stage fences are added. Existing same-execution-space ordering is retained.

CPU admission evidence: cached/uncached zero and pulse cases on a mixed120-block,4-rank mesh are byte-identical across83 snapshot/history files per case for identity and radial-map coordinates. A real dynamic vacuum92→120-block refine/derefine test produces identical complete checkpoint payloads and passes raw active/ghost metric checks. More lifecycle/restart, same-count migration, atmosphere/star and GPU tests are pending; do not interpret these short comparisons as physical stability or production approval. Cache statistics are printed per rank at shutdown. No runtime binary used by an active campaign was replaced.
