# First actual native selected-wormhole integration

The experimental `NativeCompositeEvolution` owner now accepts the dedicated
`z4c_composite_wormhole` initialization path. This is actual AthenaK Driver/RK/Task
execution, with one native Cartesian MeshBlock and owner-held composite shell
state. It is not a fully native shell pack, native AMR, device/MPI support, moving
puncture or completed scientific black-hole benchmark.

The qualified input uses M=1/3 isotropic Schwarzschild with its hyperboloidal
outer end, the Minkowski reference, positive-storage2 (log chi, log alpha/Aref),
direct signed curvature/Theta/Lambda/flux, selected physical lapse source,
tau=.02, kappa=.005, nu=1, restoring strength1 and taper width **.24**. The lapse
clock and null/fixed-angle scri data are unchanged. No floor, differential
constraint projection, CFC substitution or RHS cancellation is added. The
existing early native-pgen dispatch calls `InitializeWormhole` directly.

New input: `inputs/z4c/composite_wormhole.athinput`. It has ng3, n6, one native
Cartesian core block, seven shell radii `.45,.55,.60,.65,.70,.75,1`, dt ceiling
1e-4 and two cycles. Every MeshBlock has logical6³ active shape. There are9288
active composite cells, all retained in physical norms and snapshots. Current
native support still explicitly rejects AMR, non-Serial/device, MPI, tracker
motion and incompatible Cauchy gauges/floors.

## Representation and owner changes

`NativeCompositeFields` supports positive modes1/2/3 with old default0 intact.
The wormhole owner selects mode2. Its ghosts are reconstructed by configured
`UnpackComposite` with zero derivative jets for values, rather than the regular
Minkowski deviation formulas. Every native core and ghost point then passes
through the existing Penrose-to-physical ADM conversion. Scri diagnostics use
configured unpacking and lapse decoding as well. The old Minkowski branches,
value expressions, V1 sidecar layout and default options remain unchanged.

The wormhole branch enables the existing globally coupled topology-coarsening
preconditioner and radial-line smoothing. The first attempt using the old
Minkowski topology=false configuration failed explicitly:43blocks×3³=1161
coarsest cells exceed the preserved1024 dense-coarse limit. Enabling the already
qualified hierarchy option fixes that configuration error; no residual target,
operator, boundary, coarse limit or physical gauge was relaxed. Log derivative
enrichment is **already enabled** in the qualified run. Its remaining large core
error is not evidence that the leading log term was simply left unhandled.

Fresh initial data are generated by the actual C++ composite map's coordinate
export, then the independent existing 1D `IsotropicWormhole(mass=1/3)` sampler
at quadrature96. Active-cell centers are identical for ng2 coordinate export and
ng3 native evolution; initialization independently verifies every radius/count.
The source initializer and data SHA256, transition radius, compactification k,
minimum radius and throat radius are recorded. This is not a different initial
slice or reference.

## Restart and actual RK binding

A distinct wormhole sidecar format binds slice identifier, gauge/source version,
initial content receipt, positive mode, taper, elliptic tolerance, timestep cap,
geometry and chart parameters. Initial receipt is persisted in the native input
header and sidecar. It uses the same64-bit FNV-style checksum convention as
local restart integrity; the external evidence also records SHA256. Restart
loads the complete volume/scri/register/shift state and **does not open the
initial-data file**.

The native Driver's `rk4` is Ketcheson's four-stage2S method, not the standalone
engine's classical-RK4 `Step`. The owner therefore exports the actual live Driver
coefficient arrays for the wormhole run. `native_wormhole_reference.cpp` consumes
that receipt and the actual selected timesteps, and advances the same engine
through `NativeCompositeStageState`. It is a matched dispatch/control harness,
not independent verification of the physical equations.
