# Balance work over a complete base interval

Give every block a stable global identity and keep a dense pack on each rank. Partition the donor graph using the work in each temporal level and stage class, memory, sparse transfer volume and transfer frequency. Score candidate placements using measured batch costs and task dependencies. Sparse fast regions may occupy a subset of ranks.

Redistribute only at common endpoints when predicted remaining savings cover migration and rebuilding with a safety margin. Migrate accepted values and diagnostic ledgers exactly. Replay the recorded ownership schedule for restart comparisons. Wall time per simulated mass at matched accuracy determines whether a partition improves production throughput.


The spread mode uses the same weighted candidates and cost model. It exchanges fine and slower leaves to give each physical GPU a share of the highest temporal level, then distributes those leaves among each GPU's tile ranks. These exchanges preserve per-rank block counts. Write the per-rank finest counts with each placement so coverage can be verified against hardware binding.

The driver advances each coarse interval through a native pack TaskList. Its multirate task polls the private ready queues and MPI requests, runs one ready batch and yields an incomplete status until the endpoint is accepted. Transport metadata setup compiles peer demand at placement changes. The receive window uses two records per remote donor, exact source and stage tags, and alternating epoch tag banks.
