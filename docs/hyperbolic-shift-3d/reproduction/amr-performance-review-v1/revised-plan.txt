REVISED PERFORMANCE AND SCALING PLAN — AFTER EXTERNAL REVIEW

Status: planning only. Supersedes the proposed phase ordering and ownership recommendation in review-prompt.txt. Solver base remains c16a7c212acb00e9f963cb9a9f42d5d886777a7e. No optimization, evolution, remote operation or campaign change was executed during this revision.

Assessment of the external review

I agree with the main judgment: measure the current driver first; prioritize steady-step work and replicated memory; distinguish evolution ownership from native regrid ownership; do not assume weighted partitions will help; and preserve the numerical failure/counter contracts. Native arrays are used for topology-changing transfers, not RK evolution. The separate native partition costs bridge transfers and restricts admissible rank counts; it is not itself the cause of steady-stage imbalance.

Confirmed corrections to the original prompt:
- The native Mesh requires a Cartesian leaf on every rank. Default 2x2x2 initialization and the eight-leaf coarsened state cap this case at eight ranks. This is more than an admission guard.
- The existing LoadBalance algorithm does not construct valid metadata for skipped/empty ranks. A read-only reproduction of its loops with costs [10,1,1] on three ranks assigns all leaves to rank 2 but populates metadata as though rank 0 owned them, leaving other entries untouched. See review-checks.json. Do not inject unequal costs into this native path or remove its guard without addressing this contract.
- Diagnostic Fill increments boundary chi-sign counters; Capture persists them. Cadence changes can also change FastFlow warm starts, final radius seeds and diagnostic extrema. Different diagnostic cadence is not a whole-checkpoint-equivalent experiment even if evolved fields agree.
- Coordinated plans are not directly selectable: a chi-floor static_assert excludes this target, measured partitions are incompatible with that path, and fixed ContinuousCoreMesh constructors/numerical defaults require explicit changes. Reuse the transaction/epoch pattern, not a macro toggle.
- The new Evolution is built before native gathers. Peak memory must include both generations, snapshots, native arrays, gather outputs and TransferExtra outputs simultaneously.
- The actual radial consumer is PointKernel::BuildJet, not LoadJet. It samples fields 0–27, with second derivatives for 11 fields. The generic cache stores 31*(3+9)=372 derivative components per selected row; this consumer uses 28*3+11*9=183 stored components. Counting symmetric second derivatives independently instead gives 150 of 279. Neither ratio is a predicted speedup, and other consumers must be audited.
- Direct device pointers are passed to MPI. The current GPU path requires GPU-aware MPI; there is no automatic host-staging fallback.
- AMR report seconds is a rank-zero duration excluding initial setup and including final capture/write. Existing phase timers disappear with the old Evolution unless accumulated explicitly.

Qualifications and disagreements:
1. Do not adopt “exactly two ownership intervals per rank” as a general design. It holds when a rank owns one contiguous run of whole blocks in the combined nominal ordering, plus that run's overlap tail. Independently assigning a Cartesian range and stable shell tiles generally creates multiple nominal and overlap ranges. Aligning outer-shell/surface ownership can add further restrictions. Prove representability on real fixtures or explicitly design bounded segment lists. For example, a rank assigned an early Cartesian block and a later shell block can need two separated nominal ranges and two separated overlap ranges. Two binary searches are not a sufficient general owner map. Likewise, snapping cuts in the nominal prefix alone does not align appended overlap ownership.
2. Shell/surface co-location may reduce normal donor traffic, but angular/mixed-derivative halos remain. Do not promise elimination of the normal halo plan without deriving its complete read set.
3. The send-buffer warning is a credible capacity hazard, not an observed overrun in our validated runs. For N12/ng4, a refined-child message contains 14^3 values per field; eight messages contain 21,952 versus 20^3=8,000 values per allocated parent slot. Actual messages depend on legal topology, balancing and destinations. Prove bounds for metadata AND send/receive payloads using admissible-tree stress fixtures; do not treat the “36% of capacity” estimate as a universal failure threshold. No new capacity shrink is approved.
4. A collective capacity check before tree mutation requires topology preflight or a rollback-capable transaction. Simply moving an MPI reduction cannot make the existing mutating sequence transactional. A rank-local exit risks inconsistent termination/deadlock or launcher abort; a hang is not inevitable on every MPI implementation.
5. The exact collective/host-reduction counts in the review are useful estimates, not established profiles: cache hits, diagnostics, tracker and failure branches alter them. Instrument actual calls. Hardware/core counts and affinity must also be recorded from the benchmark machine rather than copied from another review.
6. Do not reject every discontiguous ownership design a priori or choose empty native ranks over a subcommunicator solely by source-site counts. Compare changes, invariants, migration cost and failure behavior. No general ownership redesign is selected yet.
7. Small tracker/base-copy optimizations are low priority, but their benefit cannot be declared negligible for every backend without measurement. Base storage also matters at larger problem sizes. Repeated growing/shrinking of transfer buffers is undesirable; their lifecycle may still be redesigned safely with proven sizing and persistent capacity.
8. Do not mechanically revert an entire milestone for every byte difference or accounted metadata increase. Preserve the evidence, localize the difference, and reject unapproved arithmetic/science changes. Cadence metadata and documented horizon restart variation require explicitly different comparison rules.

The derivative, prolongation and halo arithmetic, all31 fields and compensation, scientific settings, floors/sign accounting, tracker and scri closure remain fixed. Dynamic boosted refinement still produces negative chi at the first regrid; its admissibility is an independent numerical blocker. Performance work must retain its detection and raw failure evidence. Fixed-hierarchy and uniform runs are valid optimization controls; smooth dynamic runs remain valid regrid controls. None proves robust dynamic boosted evolution.

Descending priorities

1. Establish a trustworthy baseline and safety gates.
   First implementation milestone: instrumentation only, default behavior unchanged. Export per-rank setup, steady-stage compute, communication/wait, diagnostics, regrid subphases and checkpoint timing/call counts. Preserve totals across generations. Record workload by Cartesian level/shell layer/overlap, radial/normal/surface rows, halo entries, sparse bytes/peers and memory by structure, including temporary coexistence. Keep overlapping error_sync separate from exclusive accounting. Add optional profiling synchronization with its overhead measured separately; do not silently add production fences.
   In the same planning stage, specify focused native empty-rank/unequal-cost and buffer-bound tests. These are mandatory gates before changing native costs, capacity, rank participation or migration. Do not expand generic-native scope inside the instrumentation patch.
   Freeze source, executable, compile flags, input topology and diagnostic settings. Run isolated matched-P A/B repeats on CPU Serial at P=1,2,4, with warmup and at least three alternating pairs initially. Record the heterogeneous host/affinity limitations. Treat all existing six-step wall times as qualification costs, not a scaling curve.

2. Reduce repeated diagnostic/data-transfer work, then test excess radial work.
   First optimization patch: DownloadOwnedPadded should copy the exact selected/required block set into persistent host storage instead of every block between min/max indices. Preserve complete support for moving FastFlow samples and tracker/diagnostic consumers; poison unfilled regions in tests. Compare field checkpoints and horizon histories at unchanged cadence. This targets a confirmed transfer amplification without changing ownership.
   Add optional diagnostic/constraint/FastFlow cadence only as an explicit benchmark/runtime feature. Default cadence1 must reproduce current state and counters. At different cadences compare evolution/surface/compensation/tracker arrays separately and report sign-ledger/seed/history differences. Keep matched cadence in any claimed A/B end-to-end speedup. Separating diagnostic-only event counters is a separately reviewed semantic change, with a nonzero-event fixture.
   Next isolated compute experiment: specialize radial Prepare to the verified consumer's field/derivative needs while retaining the generic all-field API and zero-second-derivative contract. Preserve every consumed summation order and per-stage refresh. Test all consumers, changed input states, empty/noncontiguous ownership, and CPU/device parity. Accept only if kernel and end-to-end measurements support it; field batching itself is already enabled.

3. Make memory and work scale with local ownership/dependencies.
   Main storage target: compact bulk and sampled-normal padded buffers with explicit global-block→local-slot maps and exact donor read sets. Keep checkpoint/global logical identities independent of in-memory layout. Test all KO, FD, mixed, advection, scri and moving-horizon reads under NaN poisoning and after regrid/restart. Existing 15-leaf N12 padded buffers consume 424 MiB/rank before other allocations.
   Then assess compact owned-plus-donor stage storage and narrower accepted-state backups with full rollback/re-exchange proof. Remove genuinely unused host/reference copies only after auditing consumers. Do not remove complete checkpoint/failure gathers prematurely.
   Include native storage in the memory budget. At N12, fine/coarse state+compensation allocate 528.54 MiB at capacity104 or 162.63 MiB at capacity32. Registration additionally reserves about787.11/242.19 MiB for send+receive buffers, giving roughly1315.65/404.82 MiB combined before metadata. These are allocation formulas, not measured peak RSS. Native buffers are only used during regrid but remain resident; review lifecycle/lazy provisioning as a later memory candidate, preserving proven bounds and avoiding reallocation churn.
   Measure per-rank and aggregate memory, old/new peak coexistence, and end-to-end cost. Do not assert a fixed 2–3x saving before including halo dependencies and mapping overhead.

4. Remove the rank ceiling safely; optimize coupled ownership only if justified.
   Treat native participation and stage balance as separate problems. The first gates are correct empty/skipped-rank metadata, collective capacity/payload validation, and transactional failure handling. Compare explicitly supported shell-only ranks, a Cartesian communicator, and admissible prepartitioned topology initialization. Initialization alone cannot solve a later coarsen-to-eight-leaves event on more than eight participants. Do not simply remove the guard or reduce root-block size to claim strong scaling on the same problem.
   After current-stage profiling, test a measured partition only if meaningful imbalance remains. Include bulk, interpolation, normal/scri, communication, memory and fixed launch costs; fit on multiple partitions and validate critical-path predictions on held-out cases. Historical V11 rank-average bulk weighting failed; the later batching optimization removed most of that particular imbalance. Reject a cost model that has no predictive or timing benefit.
   Prefer stable whole-block/tile identities and localized surface donors, but prove the ownership representation. Preserve global checkpoint order; use explicit interval/segment maps if independent Cartesian/shell assignments require them. Enumerate changes to sparse owner lookup, local fields, overlap cells, horizon central-cell ownership, counters and collectives. Stable shell ownership is an optimization objective, not permission to worsen the critical rank indefinitely.
   Reuse native migration and transaction patterns after these contracts are satisfied. Unifying evolution and native Cartesian ownership can then remove the full-gather regrid bridge. An ownership-only rebalance path must be tested rather than assumed to be RedistAndRefineMeshBlocks(...,0,0).
   This scaling-design track can run alongside memory work; it is required before mixed-AMR benchmarks above eight ranks. A fixed uniform 64-root control can already support a larger rank matrix in principle and is a distinct workload, subject to local/GPU resource limits.

5. Accelerate setup/restart and regridding where measured.
   Replace repeated linear leaf searches with a logical-location/spatial index, retaining exact finest-valid-owner selection, boundary tolerance, tie-breaking, external overlap validity and fallback semantics. CompositeMesh::Owner and InterpolateAMRCartesian do not have identical validity domains; do not conflate them. Verify identical owner/rows on 8/15/22/71-leaf fixtures and boundary/corner queries. Measure construction versus leaf count; fixed-N setup can become quadratic in Cartesian leaves.
   Bundle only independently reviewable direct-copy Load paths and precomputed fixed-shell copy offsets. A Cartesian-overlap-only coordinate map is valid only if it preserves the old exact-match donor precedence wherever shell/Cartesian coordinates coincide; prove this before pruning entries. Cache Load rows only if actual reuse amortizes construction—topology changes can make a persistent cache useless. Use live-block restriction/copy bounds after generic Z4c checks. Retain immutable shell geometry only when its generation-specific indices and interface donors have an explicit remapping contract.
   Regrid-only improvements rank below steady-step/memory work unless profiles or frequent restart show otherwise. Counter/checkpoint snapshots and failure behavior must remain complete.

6. Defer low-evidence micro-optimizations and asynchronous execution.
   Persistent tracker scratch, owned-base copies, kernel fusion/specialization, neighbour/persistent collectives and overlap are candidates, not mandatory deliverables. Pursue them only after a measured cost justifies complexity. Keep cheap replicated surface projection/angular work unless current data favor distribution. Never remove error checks; reduction fusion needs an explicit dependency/failure proof. MPI progress, device readiness and rollback completion must be designed before asynchronous exchange. GPU-aware MPI is an existing requirement, not a speedup switch.

Execution milestones and acceptance

M0: instrumentation/default-cadence baseline only; separate report of native safety tests/design requirements. No ownership/layout/science change.
M1a: targeted persistent diagnostic transfers. M1b: separately measured radial derivative-mask experiment. Cadence option has its own semantics and tests. Do not bundle these to obscure attribution.
M2: local padded storage, then sparse/backup/native memory lifecycle work in distinct changes.
M3: separately reviewed native participation/ownership migration design, cost-model validation and admissible mixed-AMR scaling. No generic-native edits are hidden in M0/M1.
M4: indexed setup and regrid hygiene may move earlier if M0 demonstrates a startup/restart bottleneck. Later async work remains conditional.

Every accepted arithmetic-preserving candidate must reproduce frozen complete fields/compensation and same-cadence checkpoint metadata across rank changes, and retain the known boost rejection and donor reconstruction. New layouts need sparse/halo poisoning, stale epochs on one rank, failed publication, RK rollback, complete failure capture, changed-rank restarts around refine/coarsen, nonzero counter migration, and moving horizon/tracker coverage. Native changes additionally require main Z4c AMR regression and adversarial balance/message-bound cases. Existing zero-counter fixtures cannot validate changed event semantics.

Different cadence and FastFlow warm starts require field-versus-diagnostic comparisons; the previously observed 8.06e-10 radius difference is evidence for that fixture, not a universal tolerance for arbitrary runs. Predeclare tolerances from the operation being changed and investigate unexplained differences. Record failures without masking or deleting them.

Strong scaling holds the entire numerical mesh and event schedule fixed. Weak scaling specifies which bulk/shell/surface work grows; N12→N16 is a resolution/penalty-CFL size sweep, not automatically weak scaling. Compare matched diagnostics, time step and scientific configuration. Report setup/regrid/steady-step/end-to-end separately with uncertainty and memory. No GPU jobs, scheduler changes or remote execution are authorized by this plan revision; any later GPU qualification uses a separate reviewed execution request. No new checkpoint schema or production cadence is selected implicitly.
