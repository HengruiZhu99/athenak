5. Confirmed structural issues in the current integration

A. Two unrelated ownership schemes.
The native AMR Mesh partitions Cartesian leaves in Z order using unit block costs. RedistAndRefineMeshBlocks resets every new cost to 1.0. Shells are outside that tree. Separately, Evolution divides the global active-cell list into equal contiguous ranges; surface rows are evenly split independently. These cell cuts can split blocks and need not match native Cartesian owners. Full-state gathers bridge the representations at regrid. The native balancer therefore does not currently balance total coupled evolution cost.

B. A hard initial rank ceiling.
The default mixed/dynamic driver constructs 2x2x2 Cartesian roots before refinement. BuildTreeFromScratch rejects fewer blocks than MPI ranks, so this configuration cannot start above eight ranks even though there are 36 shell patches. Restart reconstructs the same root before refining. The stress schedule also coarsens to eight leaves. The uniform policy starts with 4x4x4 roots and has a different ceiling/problem. Increasing ranks or removing the guard is not a valid scaling solution: review initialization, minimum admissible leaves, empty/shell-only ranks, communicators/global rank assumptions and redistribution. Treat the architectural options explicitly.

C. Replicated storage and conservative dependency sets.
SparseStageExchange transfers requested values but still writes a global-sized workspace; state and base are also global-sized. Each HyperbolicCompositeExchange allocates nf*grid.count padded entries even when only selected blocks are populated. Bulk and sampled-normal have separate such workspaces. Host geometry/halo plans and some diagnostic storage are replicated. Step also deep-copies the full global-sized state into base on every rank at each accepted-step start, although local stage updates read their owned slice. Audit all rollback/failure/diagnostic uses before narrowing that backup. Regrid temporarily retains old/new generations and global snapshots.

The offline ownership audit reconstructs active ordering and verifies total active count against actual AMR1 checkpoint metadata. For N12 with 15 Cartesian leaves plus 36 shell patches:
- 124,308 evolved cells, four ranks each owning 31,077 cells.
- Bulk selected whole-block active sets contain 57,888 / 45,360 / 43,443 / 57,105 cells, BEFORE additional halo/normal/scri dependencies. These are not actual remote-send counts.
- Two full padded workspaces alone allocate 424.006 MiB PER RANK, excluding geometry, plans, state/base, native transfer buffers, scratch and host copies. The corresponding numbers for 8,22,64 Cartesian leaves are 365.809,482.203,831.384 MiB/rank.
- Nominal cells for all blocks precede appended evolved-overlap cells. A contiguous owned range can therefore touch spatially separated blocks. One four-rank range in the 15-leaf fixture has a min/max block-index span covering all 51 blocks, despite selecting only 22. DownloadOwnedPadded copies every block in that span, once per field, into a full-sized host array.
- These are structural facts/estimates, not measured speedups or total peak RSS/device memory. Hypothetical 12/24-rank rows in the audit are explicitly not successful dynamic runs.

D. Avoidable regrid work.
CartesianAMR::Load allocates a row vector even for direct active-cell copies, recomputes missing donor rows, and copies capacity-sized views. RestrictCC iterates u.extent(0), which is allocated capacity. Current capacity is max(32,96/ranks+8), e.g. 104 slots on one rank for a typical 8-22 live-leaf case. State, compensation, coarse arrays and MPI send/receive storage must be accounted for separately. Main code comments explain why persistent buffers avoid repeated device reallocation on Aurora; avoid replacing this with per-step allocation churn.

Regrid invokes native migration, then allgathers core state/compensation and constructs a complete new Evolution. It rebuilds host/device geometry, halos, sampled-normal, surface/angular and sparse plans and initializes reference arrays that will be overwritten. Some shell geometry/operators are invariant, but their global indices, interface donors or rank ownership may change. Fixed geometry does NOT imply every shell communication plan is reusable.

Cartesian InterpolateAMRCartesian linearly scans leaves per queried point. TransferExtra builds a global coordinate map over active cells, including unchanged shells, and searches shell patch identity per destination shell cell. Stable leaf/patch identities and precomputed offsets are alternatives to review.

E. Measurement gaps.
Evolution already has phase, boundary, sparse and setup timers. The AMR report exports only a small overall duration and basic counts. It replaces Evolution at each regrid, losing earlier objects' timer totals unless explicitly accumulated. Its timer starts after initial construction; suite wall time includes setup and process costs. A useful profile must preserve totals across generations, count calls and distinguish initialization, steady stages, regrid, diagnostics and checkpoint work.

F. Additional execution candidates, not established bottlenecks.
- Radial Prepare computes full first/second jets for all 31 fields. Current LoadJet samples fields 0-27; only chi, six metric components, lapse and three shifts request second derivatives. Audit every consumer/configuration before a derivative mask; preserve all31 state/transfer fields and generic API semantics. Stage-dependent jets must refresh whenever inputs change.
- Tracker allocates/uploads a small stencil at each stage and performs three device reductions plus MPI; storage could be persistent. Moving sampling coordinates must still be refreshed.
- Halo filling transposes point-major state to field-major padded storage. Measure bandwidth/layout and reuse opportunities before changing layouts globally.
- Sparse exchange is synchronous Alltoallv with collective prechecks and fences. At high rank counts global metadata/latency may dominate even when peer degree is small; current evidence does not establish that yet.
- Error/status reductions and surface gathers lie on the stage dependency chain. Do not simply remove checks or defer a failure past invalid consumers.
- Every-step constraints/FastFlow are qualification overhead. Production cadence is a configuration choice and must remain matched in A/B timing. Optional microbenchmarks can isolate their cost but cannot be advertised as equivalent end-to-end speedups.
