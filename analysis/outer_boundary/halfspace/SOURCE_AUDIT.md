# Exact production source audit

Read-only scope: source snapshot identified in `provenance.json`. The initial audit did not execute CPU/GPU repeatability controls or modify any code. The focused boundary-stencil review below records a subsequently confirmed implementation defect and reviews its repair in the task checkout.

## Confirmed unavailable-RHS-ghost read

The initial alias/task audit missed a concrete invalid stencil-input path. Original `NormalDerivative(u_rhs)` chose a one-sided derivative only in directions incident on a physical face. At an internal tangential block edge it used a centered derivative. For an off-diagonal conformal metric, raising the physical-face normal gives tangential components, so the normal derivative can read a neighboring tangential RHS ghost. The volume kernel neither computes nor exchanges that ghost. This is an unavailable-input defect, even if allocation initialization happens to leave a finite value there; it is not an in-place write/read race.

The focused repair uses `BoundaryCoordinateDerivative2` on both the residual state and its RHS: second-order one-sided differences at every local active edge and centered differences elsewhere. It preserves the same discrete derivative in the incoming characteristic amplitude and its rate. Configuration RHS fields remain immutable during the CPBC operation; no new synchronization is required. The previous formulas and arithmetic are retained wherever the old stencil was already wholly active. A diagonal raised normal therefore keeps its original path, while contributing off-diagonal tangential derivatives at local edges change intentionally.

The compiled unit regression poisons ghosts and tests quadratic data under skewed metric normals, including physical-face/internal-tangential-edge intersections. The subsequently implemented oblique-pulse MPI integration regression passed on one, two and four ranks with the same eight-block layout: nine RK stages, genuine skew normals, independently checked incoming rates and bitwise matching stage data. Details and limitations are in `BOUNDARY_STENCIL_REVIEW.md`; no GPU validation is claimed here. The implementation defect is separate from the growing continuum boundary modes in this package. Removing the ghost read neither invalidates those modes nor establishes production stability.

## Read-only race, task, and AMR audit

No concrete concurrent write/read race was found in these inspected paths. That statement does not exclude the unavailable-RHS-ghost read above. This is a source audit, not a CPU/GPU race-detector or repeatability certificate.

- `src/z4c/z4c.cpp:113`: residual u0, analytic u_bg, reconstructed u_full and u_rhs are separate allocations. Tensor wrappers alias only their corresponding allocation. Volume stencils read full/background and write RHS; dissipation reads residual and adds to RHS.
- `src/z4c/z4c_Sbc.cpp:1435` in the original snapshot: zero-rate CPBC holds the same RHS view as input/output, but spatial RHS derivatives read only chi, conformal metric, alpha and beta, which CPBC does not change. Its writes are Khat/Theta/A/Gamma; their reads are same-cell and completed before that cell's write. Incident faces have disjoint output ownership. Thus this view alias alone is not an in-place stencil race; it does not guarantee that every stencil input was computed.
- `src/bvals/physics/z4c_bcs.cpp:130`: each extrapolation kernel reads active cells along its own direction and writes ghosts. The ordered x/y/z kernels supply transverse ghost data to subsequent directions on the same default execution space. Within a kernel, stencil inputs and outputs are distinct. This relies on the documented backend execution ordering; no blanket fence is warranted without evidence of a different stream.
- `src/z4c/z4c_tasks.cpp:45`: geometry RHS waits for stress-energy; RK waits for MHD electric-field work before overwriting the geometry used by the fluid. Fluid C2P waits for Z4c-to-ADM via the Z4c excision-mask task even when actual fluid excision is disabled. Stage exchange/prolongation precedes projection/reconstruction.
- `src/bvals/bvals_cc.cpp:260`: unpack begins only after all relevant MPI_Test calls report completion. Packing fences before MPI. AMR pack also fences; AMR unpack waits for receives.
- `src/mesh/mesh_refinement.cpp:513`: AMR transfers the evolved residual, not stale analytic/full caches. `Driver::InitBoundaryValuesAndPrimitives` (`src/driver/driver.cpp:557`) reconstructs Z4c-to-ADM after the new block coordinates and ghost fills are established. `UpdateBackgroundState` always rebuilds the provider state; `src/pgen/z4c_tov_ks.cpp:1419` fills active plus ghost cells using the current block count and coordinates. No persistent stale-background path was found.
- Restriction/prolongation uses separate coarse/fine arrays and linear weighted sums. Zero residual therefore maps to zero without background interpolation. Existing `ATHENA_BVAL_RACE_DEBUG` instruments duplicate writes in coarse ghost fill/prolongation and can be enabled in the bounded AMR validation. It does not prove all transfer paths are race free.

The fourth linear ghost equals 5 f0-4 f1; at a two-face corner its tensor-product absolute weight sum is81. Thus linear extrapolation can strongly magnify an already growing active residual and make a ghost metric fail before active-cell diagnostics. This is a plausible failure amplifier, not identification of the first injection. No ghost clipping or field reset is recommended.
